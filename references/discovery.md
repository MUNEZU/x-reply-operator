# 找帖：把浏览时间变成可选择的机会

## 读取与筛选

1. 从用户主题、对话与明确经历提炼搜索方向。没有主题时，优先日本职场、AI 使用困扰、开发与产品、日常不便中有事实依据的领域，不强制垂类技术内容。
2. 用已授权 X 搜索/账号浏览查看当前讨论，优先最近 24–72 小时日语帖。英文热门原帖可作日语回复来源，但语言差异不证明市场空白。旧帖有新讨论时说明原因。
3. 阅读原帖和理解主张必要的父帖/回复。逐项核实链接、发布时间、作者和互动；不可见写“不可见”，不是 0。搜索摘要是线索，不冒充完整原帖或热度依据。
4. X 不可用时，公开搜索可补链接；HN 和官网可验证话题/事实，但不能充当 X 热度。原帖无法确认则 HOLD，不推荐直接回复，不拿无关趋势替换用户主题。
5. 只看去重必要的本人回复，不全面采集档案；不能读则标去重未完成。

## 四个判断

每项用一句话解释，避免伪精确总分：

- **有人在意吗？** 实际可见阅读/讨论、新增回复和具体共鸣；大号或关键词本身不保证回复曝光。
- **接得上吗？** 直接回应主张，不只是共享关键词。
- **有我们的位置吗？** 明确经历、不同判断或可用建议；不编造差异化。
- **值得被认识吗？** 有用观察而不只是激怒；不故意曲解作者。

关联与事实可靠是硬门槛。热度高但无可信切入则 HOLD；已回复/只能空泛附和/无关则 SKIP。热度无法核验不得包装成热门帖，不设置永久点赞阈值。HOLD/SKIP 不进入编号推荐列表；必要时只在末尾用一句说明排除原因，不占候选名额。

## 输出模板

每条尽量六行：

**1. [作者与主题](确切帖子链接) — 推荐回复**

- 原帖在说：一句话，保留原意。
- 证据：作者；发布时间/时区；读取时间；可见 Views / Likes / Replies / Reposts / Bookmarks，缺项注明不可见。
- 为什么值得回：当下讨论 + 读者在意的场景。
- 你的切入：一个观点；依据为用户明确输入/公开事实/待确认。
- 示意：一句短日语切入，不提前写整篇。
- 历史：是否曾展示/起草/确认发布；本人回复去重是否完成。

末尾给优先推荐与理由，请用户选编号或发想法。零候选就结束，不自行互动。
